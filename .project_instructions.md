## SEO Architecture & Critical Rules
- **CANONICAL RULE (critical):** the root `app/layout.tsx` sets `alternates.canonical: 'https://verumpraxis.kz'`. In Next.js this is INHERITED by every child route. EVERY new page/layout MUST set its own `alternates.canonical` to its own URL, otherwise it self-canonicalizes to the homepage and Google drops it from the index. (This bug was found & fixed in June 2026 — it was the main reason only the homepage + a couple pages were indexed.)
- Per-page metadata + canonical now live in: `publications/layout.tsx`, `publications/digital-assets/layout.tsx`, `publications/legal-guide-investors/layout.tsx`, `privacy/layout.tsx`.
- Article pages (`digital-assets`, `legal-guide-investors`) each have their own server-rendered `Article` + `BreadcrumbList` JSON-LD inside their `layout.tsx`. The `/publications` listing page carries `CollectionPage` + 2-level `BreadcrumbList` (injected in `publications/page.tsx`, NOT the layout, so children don't inherit it).
- `public/llms.txt` exists for AI/GEO (AI Overview / answer engines) — keep it updated when services/pages change.
- Homepage carries `LegalService` + `Organization` + `FAQPage` JSON-LD in root layout.

## Multilingual SEO Routes (IMPLEMENTED June 2026)
- Dedicated SERVER-RENDERED homepage variants now exist: `app/en/page.tsx`, `app/kz/page.tsx`, `app/zh/page.tsx`. Each is `export const dynamic = 'force-dynamic'`, has full localized metadata (absolute title, description, keywords), own `alternates.canonical` (`/en`, `/kz`, `/zh`) + full hreflang `languages` map, localized OpenGraph locale. Each renders `<ClientApp initialLocale="en|kz|zh" />`.
- `lib/i18n/context.tsx`: `I18nProvider` accepts optional `initialLocale?: Locale`. When provided, state inits to that locale (SSR renders in that language), persists to localStorage, sets `document.documentElement.lang`, and IGNORES any stored preference. Without it, falls back to stored 'vp-locale' or 'ru'.
- `app/_components/client-app.tsx`: accepts `{ initialLocale }` and passes to provider.
- hreflang code mapping: ru→`/`, en→`/en`, **kk→`/kz`** (Kazakh hreflang is `kk`, route is `/kz`), zh→`/zh`, x-default→`/`. Kazakh uses CYRILLIC script.
- Root `app/layout.tsx` homepage `alternates` now includes the full `languages` hreflang map (homepage `/` = Russian default).
- `app/_components/header.tsx`: language switcher is ROUTE-BASED on homepage variants. `HOME_PATHS = {ru:'/',en:'/en',kz:'/kz',zh:'/zh'}`. `handleLangSwitch`: if current `pathname` is one of the 4 home paths → `router.push(HOME_PATHS[lang])` (+persist); else `setLocale(lang)` (client-side, for articles/privacy). Uses `usePathname`/`useRouter`.
- `app/sitemap.ts`: lists `/en`, `/kz`, `/zh` (priority 0.9, weekly) + homepage, all with `alternates.languages` hreflang map. siteUrl derived from `x-forwarded-host`.
- NOTE: Article/privacy pages remain single-URL bilingual (switch client-side in place). Only the HOMEPAGE has dedicated language routes so far. Future iteration could add `/en/publications/...` etc. if needed.
- After any deploy of SEO changes, advise user to request indexing in Google Search Console + Yandex Webmaster.

## verumpraxis.com (второй домен)
- verumpraxis.com — ЭТО СОБСТВЕННЫЙ САЙТ КЛИЕНТА (не сторонний). Клиент создал его намеренно как дубликат АНГЛИЙСКОЙ версии verumpraxis.kz для англоязычной аудитории.
- Сейчас .com обгоняет verumpraxis.kz по бренд-запросу «Verumpraxis» в Google.
- SEO-риск: два идентичных английских сайта (verumpraxis.kz/en и verumpraxis.com) = дублированный контент, домены конкурируют. На .kz технически прописано canonical: https://verumpraxis.kz/en и hreflang en → verumpraxis.kz/en (в app/layout.tsx, app/en/page.tsx, sitemap.ts, LANGUAGES const). Это конфликтует с существованием .com.
- РЕШЕНО (Вариант А, реализовано + задеплоено на verumpraxis.kz): verumpraxis.com сделан каноническим адресом для английской версии. Клиент подтвердил, что .com на ДРУГОЙ платформе и он МОЖЕТ править его код (в т.ч. <head>).
